When do I reach for this?

Fast matrix multiplication is a black box: two \(n\times n\) matrices multiply in \(O(n^\omega)\) time, \(\omega\le 2.373\) (naïvely \(n^3\)). The exam skill is reduction: recast a graph or counting problem as a matrix product (or a matrix power) so you beat \(O(n^3)\). Powers of the adjacency matrix count walks; repeated squaring computes high powers cheaply; and randomness lets you verify a product faster than you can compute it.

  • "Count walks / triangles / reachability" → powers of the adjacency matrix \(A\).
  • "Transitive closure / diameter in \(o(n^3)\)" → \((A+I)^k\) via repeated squaring + search.
  • "Compute \(Av_1,\dots,Av_n\)" → stack the \(v_i\) into a matrix, one product (economy of scale).
  • "Check \(C=AB\) fast" → Freivalds' randomized verifier in \(O(n^2)\).

Core tools

STRASSEN / EXPONENT ω
Strassen multiplies \(2\times2\) blocks with \(7\) multiplications instead of \(8\): \[ T(n)=7\,T(n/2)+\Theta(n^2)=\Theta(n^{\log_2 7})=\Theta(n^{2.81}). \] Only the number of multiplications matters: multiplying \(m\times m\) with \(k\) mults gives \(\omega\le\log_m k\). Known: \(2\le\omega\le2.373\). any dense product; a subroutine you invoke as \(O(n^\omega)\)
WALK COUNTING
For adjacency matrix \(A\), \((A^k)_{i,j}=\#\{\text{walks of length }k\text{ from }i\text{ to }j\}\). So \((A^k)_{i,j}>0\iff\) some walk of length \(k\) exists; \(\operatorname{tr}(A^3)/6=\#\)triangles. reachability, path existence, counting closed walks
BINARY EXPONENTIATION
Compute \(A^k\) with \(O(\log k)\) products: square repeatedly \(A^{2^{j}}=(A^{2^{j-1}})^2\), then multiply the factors picked out by the binary digits of \(k\): \[ A^{k}=\prod_{j:\,c_j=1}A^{2^j},\qquad k=\sum_j c_j 2^j. \] you need a single high power \(A^k\) (or a search over powers)
FREIVALDS' VERIFIER
To test \(C=AB\) in \(O(n^2)\): pick random \(v\in\{0,1\}^n\), check \(A(Bv)=Cv\) using three matrix–vector products. If \(C=AB\) always passes; if \(C\neq AB\), \((C-AB)\) is nonzero, so \(v\) fools it with prob. \(\le\tfrac12\) (Schwartz–Zippel, \(d=1\)). verify a claimed product faster than recomputing it

Worked example — the thinking

2024B P4. Compute the diameter of a strongly connected digraph in \(o(n^3)\) (deterministically).

  1. Turn reachability into a matrix power. Use the lazy walk matrix \(B=A+I\). Then \((B^k)_{i,j}>0\iff\) there is a walk from \(i\) to \(j\) of length \(\le k\) — the "\(+I\)" lets shorter paths persist as \(k\) grows.
  2. Distance \(=\) smallest good power. \(d(i,j)\) is the least \(k\) with \((B^k)_{i,j}>0\); the diameter is the least \(k\) for which all entries of \(B^k\) are positive.
  3. Monotonicity → binary search. "All entries positive" only becomes truer as \(k\) grows, so binary-search \(k\in\{1,\dots,n\}\).
  4. Cost. Each tested power is one binary exponentiation, \(O(n^\omega\log n)\); with \(O(\log n)\) search steps that is \(O(n^\omega\log^2 n)=o(n^3)\). (Precomputing \(B^{2^0},\dots,B^{2^{\log n}}\) once shaves a log.)
Theorem Linear-algebra facts you can quote. \(\operatorname{rank}(A)=\operatorname{rank}(A^\top A)\) (equal kernels). \(A\) is PSD \(\iff\) \(v^\top Av\ge0\) for all \(v\) \(\iff\) all eigenvalues \(\ge0\) \(\iff\) \(A=B^\top B\) for some \(B\). \(\det A=\prod\lambda_i\); the coefficient of \(x^{n-1}\) in \(\det(xI-A)\) is \(-\operatorname{tr}A\). A symmetric matrix with \(\det\ge0\) need not be PSD (e.g. \(-I\) in even dimension).
Traps. Reducing to matrix multiplication only beats \(n^3\) if \(\omega<3\) — always cite the \(O(n^\omega)\) black box, don't silently assume \(n^{2.37}\) is free of the \(\log\) factors from squaring/search. Boolean product: cast \(0/1\) entries to integers, multiply, then threshold \(>0\) — over the booleans there is no fast algorithm directly. Diameter/APSP tricks need the graph connected (or handle \(\infty\) distances). Repeated squaring gives a single power in \(O(\log k)\) — computing all powers \(A,A^2,\dots,A^n\) still costs \(n\) products.

Checklist

  1. Express the quantity as a product, a power, or "smallest \(k\) with \(A^k\) positive".
  2. Replace \(A\) by \(A+I\) if you want "length \(\le k\)" instead of "exactly \(k\)".
  3. Use binary exponentiation for high powers; binary-search the threshold if it is monotone.
  4. Count products \(\times\,O(n^\omega)\); add the \(\log\) factors honestly and confirm \(o(n^3)\).
  5. To only verify a product, use Freivalds in \(O(n^2)\) instead of recomputing.
