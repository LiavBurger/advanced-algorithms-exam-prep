The algorithm sweeps the subsets in any order, and whenever it meets a subset not yet hit by \(X\), it adds all of that subset's (at most \(3\)) elements to \(X\).

  1. Initialize \(X=\emptyset\).
  2. For each subset \(D\in C\), in arbitrary order: if \(X\cap D=\emptyset\), set \(X\leftarrow X\cup D\); otherwise do nothing.
  3. Return \(X\).

This returns a hitting set: after we process a subset \(D\), we always have \(X\cap D\ne\emptyset\), because either it was already hit before we reached it, or we just added all of its elements to \(X\).

It runs in polynomial time: there are \(|C|\) subsets, and for each we test \(X\cap D=\emptyset\) and possibly add at most \(3\) elements, which is cheap. (A key property for the analysis in part (b): we add \(D\) only when it currently shares nothing with \(X\), so the fully-added subsets are pairwise disjoint.)

Intuition. Grab an entire unhit subset at once; that both guarantees coverage and keeps the grabbed subsets disjoint.
