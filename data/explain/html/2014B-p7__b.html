Now the number of bins is fixed (given as input, say \(m\) machines), all bins share one common capacity, and we want the smallest capacity that lets all items fit. This is exactly the makespan / load-balancing problem: minimize the maximum load over \(m\) bins.

Key idea: the minimum feasible capacity equals the minimum achievable maximum load. So run the greedy least-loaded scheduler and report the max load it produces.
  1. Reformulation. If every bin has capacity \(C\), all items fit iff we can assign items to the \(m\) bins with every bin's total load \(\le C\). The least \(C\) for which this is possible is precisely \(\min_{\text{assignments}}(\text{max bin load})\). So minimizing capacity = minimizing makespan.
  2. Algorithm (greedy list scheduling). Process items one by one; place each item into the currently least-loaded bin. Output the maximum bin load of the resulting packing as the capacity.
  3. Why 2-approximation. This is the scheduling result proved in pset 2 (problem 3): greedy least-loaded assignment yields a maximum load at most twice the optimal makespan. Two standard lower bounds drive it — the optimal makespan is at least the average load \(\tfrac1m\sum_i w_i\), and at least the largest single item \(\max_i w_i\). When the greedy max-load bin last received an item, that bin was the least loaded, so its load-before-adding was \(\le\) average \(\le \mathrm{OPT}\); adding one more item (size \(\le \mathrm{OPT}\)) keeps it \(\le 2\,\mathrm{OPT}\).
  4. Conclusion. The reported capacity (= greedy's max load) is at most \(2\) times the minimum feasible capacity, giving a 2-approximation, computable in polynomial time.
