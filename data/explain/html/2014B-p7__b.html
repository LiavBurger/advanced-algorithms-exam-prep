Goal With the number of bins fixed, give a 2-approximation for the smallest common bin capacity that fits all items.

Strategy Recognize this as minimizing the maximum load over \(m\) bins, then run the greedy least-loaded scheduler and report its max load.

Key idea The minimum feasible capacity is exactly the minimum achievable maximum bin load — so a good makespan algorithm solves it.

Why this move "Minimize the largest bin" is the makespan problem already solved in class, whose greedy list-scheduler is a known 2-approximation.

  1. Reformulate. With capacity \(C\), all items fit iff we can assign them so every bin's load is \(\le C\). The least such \(C\) is exactly \(\min(\text{max bin load})\), so minimizing capacity equals minimizing makespan.
  2. Algorithm. Process items one by one, placing each into the currently least-loaded bin; output the resulting maximum bin load as the capacity.
  3. Why it's within 2. This is the pset-2 scheduling result. Two lower bounds on the optimal capacity: it's at least the average load \(\tfrac1m\sum_i w_i\), and at least the largest item \(\max_i w_i\). When the busiest bin got its last item, that bin was least-loaded, so its load-before was \(\le\) average \(\le \mathrm{OPT}\); one more item (size \(\le \mathrm{OPT}\)) keeps it \(\le 2\,\mathrm{OPT}\).
  4. Conclusion. The reported capacity is at most twice the minimum feasible capacity, a 2-approximation running in polynomial time.
