Claim False — the greedy algorithm is not a \(2\)-approximation for maximum cut.

Strategy Trace the algorithm carefully and show it can put every vertex on one side, giving a cut of value \(0\).

Key idea Both sides start empty and the test is a strict "more neighbors in \(S\)", which no vertex can ever pass, so everything drifts to \(T\).

Why this move To refute an approximation claim, the cleanest move is one instance where the algorithm's output is \(0\) but the optimum is positive, making the ratio unbounded.

  1. Read the rule. \(S\) and \(T\) both start empty. A vertex \(w\) joins \(S\) only if it has strictly more neighbors in \(S\) than in \(T\); otherwise it joins \(T\) (ties go to \(T\)).
  2. First vertex. With both sets empty, \(w\) has \(0\) neighbors in each; \(0>0\) is false, so \(w\) goes to \(T\), leaving \(S\) empty.
  3. Everything follows to \(T\). As long as \(S\) is empty, every vertex has \(0\) neighbors in \(S\), so it never has strictly more there — it always joins \(T\). Hence all vertices end in \(T\) and \(S=\varnothing\).
  4. The cut is zero. With \(S\) empty, no edge crosses, so the cut value is \(0\), while any graph with an edge has optimum at least \(1\).

Since the algorithm outputs \(0\) while the optimum is positive, no constant ratio (let alone \(2\)) can hold, so the claim is refuted.
