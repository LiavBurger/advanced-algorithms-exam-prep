Claim True: a polynomial-time algorithm for integer linear programs would imply \(\mathrm{P}=\mathrm{NP}\).

Strategy Encode an NP-complete problem (maximum independent set) as an ILP; a fast ILP solver would then solve it fast, forcing the collapse.

Key idea ILP is NP-hard because \(0/1\) variables plus linear constraints can express NP-complete problems, and it is itself in NP.

Why this move "Would a fast algorithm imply \(\mathrm{P}=\mathrm{NP}\)" is answered by exhibiting a reduction from a known NP-complete problem into the problem in question.

  1. Set up variables. Given a graph \(G=(V,E)\), introduce a \(0/1\) variable \(x_v\) for each vertex, meaning "\(v\) is chosen".
  2. Encode independence. For each edge \((u,v)\) add \(x_u+x_v\le 1\), so no two adjacent vertices are both chosen; the chosen set is independent.
  3. Objective. Maximize \(\sum_v x_v\); the optimum equals the maximum independent set size, and this ILP is built in polynomial time.
  4. Collapse. Since maximum independent set is NP-complete and ILP is in NP, a polynomial-time ILP solver would decide an NP-hard problem in polynomial time, giving \(\mathrm{P}=\mathrm{NP}\).
