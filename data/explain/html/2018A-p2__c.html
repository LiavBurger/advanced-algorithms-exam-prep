In the online version the subsets \(D\) arrive one at a time; after each arrival \(X\) must already hit everything seen so far, and once an element is added it can never be removed. We must be \(3\)-competitive: our final \(|X|\) at most \(3\) times the optimal hitting set for the whole (final) instance.

Online algorithm: keep the greedy from part (a). When a new subset \(D\) arrives, check \(X\cap D\). If \(X\cap D=\emptyset\), add all of \(D\): \(X\leftarrow X\cup D\). Otherwise leave \(X\) unchanged.
  1. The key observation is that the offline greedy of part (a) already processes subsets in an arbitrary order and never revisits or removes a decision. Its analysis did not rely on knowing future subsets.
  2. Therefore we may let "arbitrary order" be exactly the online arrival order. Each arriving \(D\) is handled with the same rule, using only \(X\) as it currently stands.
  3. The requirement is met at every step: after we process an arriving \(D\), we have \(X\cap D\ne\emptyset\) (either it was already hit, or we just added all of \(D\)), so \(X\) hits all subsets seen so far. Decisions are irrevocable, matching the online rules.

Since the final \(X\) is identical to what the offline greedy would produce on that sequence, part (b)'s bound \(|X|\le 3\,\mathrm{OPT}\) applies verbatim. Hence the same greedy is a \(3\)-competitive online algorithm.
