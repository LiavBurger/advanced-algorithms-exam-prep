We use one binary variable per edge and cap each vertex's degree, with the only twist being that \(V_2\)-vertices may take two edges instead of one. For each edge \(e\in E\) let \(x_e\in\{0,1\}\), where \(x_e=1\) means \(e\) is selected. The objective maximizes the number of selected edges, and there is one constraint per vertex: each \(V_1\)-vertex may touch at most one selected edge, each \(V_2\)-vertex at most two. The program is

\[\max\ \sum_{e\in E}x_e\quad\text{s.t.}\quad \sum_{e\ni v}x_e\le 1\ \ \forall v\in V_1,\qquad \sum_{e\ni v}x_e\le 2\ \ \forall v\in V_2,\qquad x_e\in\{0,1\}.\]

Any feasible \(0/1\) vector respects both caps, so it is a semi-matching, and the objective counts its edges; an optimal solution is a maximum semi-matching.

Intuition. One on/off switch per edge, and each side of the graph gets its own degree cap.
