Goal Turn an always-correct Las Vegas algorithm \(A\) (expected time \(\le 10n\)) into a Monte Carlo algorithm \(B\) running in \(O(n)\) time and correct with probability at least \(9/10\).

Strategy Run \(A\) as a black box but cut it off after a fixed step budget, returning a default answer if it hasn't finished.

Key idea \(A\) only "fails" \(B\) when it runs unusually long, and a long run is rare because its expected time is small.

Why this move To bound the probability of a large running time from just its expectation, Markov's inequality is the natural tool, so you set the cutoff as a multiple of the expected time.

  1. Algorithm \(B\). Run \(A(x)\) for at most \(100n\) steps. If it finishes, output its answer; otherwise halt it and output \(0\).
  2. Running time. \(B\) never runs past \(100n\) steps, so it is \(O(n)\) on every execution.
  3. When it errs. If \(A\) finishes, its answer is correct (Las Vegas), so \(B\) is correct. The only error is when \(A\) doesn't finish in \(100n\) steps and \(B\) outputs the default \(0\).
  4. Bound that chance. Since \(T(n)\ge0\), Markov gives \(\Pr[T(n)\ge 100n]\le \tfrac{\mathbb{E}[T(n)]}{100n}\le \tfrac{10n}{100n}=\tfrac1{10}\).

So \(B\) is wrong with probability at most \(1/10\), i.e. correct at least \(9/10\) of the time. The bound uses only \(\mathbb{E}[T(n)]\le 10n\), so it depends on the algorithm's randomness, not on the input.
