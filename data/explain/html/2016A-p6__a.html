Goal write maximum-weight matching as a binary integer program.

Strategy put one \(0/1\) variable on each edge saying whether it is picked, maximize the total weight of picked edges, and stop any vertex from being used twice.

Key idea a matching is exactly a set of edges where no vertex is used more than once, and "used at most once" is a linear inequality at each vertex.

Why this move the definition of a matching is a local rule per vertex (degree at most one), so it drops straight into one constraint per vertex — the natural way to turn it into an ILP.

  1. Choose the variables. For each edge \(uv\in E\) let \(x_{uv}\in\{0,1\}\), with \(1\) meaning "this edge is in the matching."
  2. Write the objective. We want the heaviest matching: \(\max \sum_{uv\in E} x_{uv}\,w(uv)\).
  3. Add the matching constraint. At each vertex \(v\), the picked edges touching it may total at most one: \(\sum_{uv\ni v} x_{uv}\le 1\).
  4. Force integrality. Require \(x_{uv}\in\{0,1\}\) so each edge is fully in or fully out.

Any feasible \(0/1\) vector covers each vertex at most once, so it is exactly a matching, and its objective value is that matching's weight.
