We turn the Monte Carlo algorithm (whose expected number of operations is at most \(cn\)) into a Las Vegas style algorithm:

  1. Run the selection algorithm, but keep a counter of the operations performed and abort the run as soon as it reaches \(2cn\) operations.
  2. Repeat this capped run up to \(5\) times.
  3. If some run finishes within \(2cn\) operations, return its answer. If all \(5\) runs are aborted, return the first element of the array.

Operation count: each run performs at most \(2cn\) operations, and we do at most \(5\) runs, so at most \(10cn\) operations inside the runs. Maintaining the counter and controlling the runs adds only a constant factor, and the whole thing can be arranged so the total does not exceed \(25cn\) operations. So the algorithm always performs at most \(25cn\) operations.

Correctness probability: a run gives the correct answer whenever it finishes within its \(2cn\) budget (a completed selection run is always correct). Let \(T(n)\) be the running time of a single run, so \(E[T(n)]\le cn\). By Markov's inequality, \[\Pr[T(n)>2cn]\le \Pr\big[T(n)>2E[T(n)]\big]\le \frac{E[T(n)]}{2E[T(n)]}=\frac12.\] The \(5\) runs are independent, so the probability that all of them exceed the budget (the only way we fail) is at most \(\left(\tfrac12\right)^5=2^{-5}\). Hence the algorithm returns the correct answer with probability at least \(1-\tfrac{1}{2^{5}}\).

Intuition. Cap each run so it can't run long, and since each run beats the cap at least half the time, five independent tries almost never all fail.
