Goal give an efficient algorithm that finds a vertex cover at most \(3\) times the optimum in a 3-uniform hypergraph, where every edge is a triple \(\{u,v,w\}\) and a cover must hit every triple.

Strategy repeatedly grab an uncovered edge, throw all three of its vertices into the cover, and delete every edge they touch; then charge the cost against a set of disjoint edges.

Key idea the edges we pick are pairwise disjoint, and any cover must spend at least one distinct vertex on each of them — so the optimum is at least the number of picks, while we spend exactly \(3\) vertices per pick.

Why this move this is the same maximal-matching trick behind the classic \(2\)-approximation for vertex cover in ordinary graphs; edges here hold \(3\) vertices instead of \(2\), so the ratio simply climbs from \(2\) to \(3\).

  1. Greedy loop. Start with \(C=\varnothing\). While edges remain: pick any edge \(\{u,v,w\}\), add all three vertices to \(C\), and erase every edge that contains at least one of \(u,v,w\). Each round removes at least the picked edge, so this finishes in polynomial time.
  2. What we spent. Let \(k\) be the number of rounds. Each round adds exactly \(3\) vertices, so \(|C|=3k\).
  3. The picked edges are disjoint. When an edge is picked, every other edge sharing a vertex with it is erased, so a later pick shares no vertex with the earlier ones. The \(k\) picked edges are therefore pairwise vertex-disjoint.
  4. Lower bound on the optimum. Any valid cover must contain a vertex from each picked edge, and since these \(k\) edges share no vertices, that forces \(k\) distinct vertices. Hence \(\mathrm{OPT}\ge k\).
  5. Put it together. \(|C|=3k\le 3\,\mathrm{OPT}\), so the algorithm is a \(3\)-approximation.

There's also an LP version: write \(\min\sum_v x_v\) with \(x_u+x_v+x_w\ge 1\) per edge, relax \(x_v\in\{0,1\}\) to \(0\le x_v\le 1\), solve, and round \(x_v\) up to \(1\) exactly when \(x^{*}_v\ge\tfrac13\). Every edge's three values sum to at least \(1\), so one of them is at least \(\tfrac13\) and gets rounded up — the edge stays covered — and each rounded-up variable had \(x^{*}_v\ge\tfrac13\), so the cost grows by at most a factor of \(3\). Same \(3\) either way, which is the intuition to hold onto: a triple simply costs you three where a pair cost two.
