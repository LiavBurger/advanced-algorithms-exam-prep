We never need more than \(n\) bins (in the worst case one item per bin), so index the possible bins by \(j\in\{1,\dots,n\}\). Use two kinds of \(0/1\) variables: \(y_j\in\{0,1\}\), where \(y_j=1\) means bin \(j\) is used; and \(x_{ij}\in\{0,1\}\), where \(x_{ij}=1\) means item \(i\) is placed in bin \(j\). The integer program is

\[\min\sum_{j=1}^{n}y_j\]

\[\text{s.t.}\quad \sum_{j=1}^{n}x_{ij}=1\ \ \forall i\in\{1,\dots,n\},\qquad \sum_{i=1}^{n}w_i x_{ij}\le B\,y_j\ \ \forall j\in\{1,\dots,n\},\]

\[x_{ij}\in\{0,1\},\qquad y_j\in\{0,1\}.\]

The objective \(\sum_j y_j\) counts the used bins, which we minimize. The first constraint puts every item in exactly one bin. The second constraint does two jobs at once: whenever bin \(j\) is used (\(y_j=1\)) its total weight is at most \(B\); and if any item is placed in bin \(j\), the left side is positive, which forces \(y_j=1\) so the bin is counted (and if \(y_j=0\) the right side is \(0\), forbidding any item there since all \(w_i\ge 0\)).

So every feasible \(0/1\) solution assigns each item to exactly one bin, respects every used bin's capacity \(B\), and has objective equal to the number of nonempty bins — that is exactly a valid packing and its cost. Conversely any real packing gives a feasible \((x,y)\) of the same cost. Therefore minimizing \(\sum_j y_j\) gives the fewest bins.

Intuition. One variable says "bin open," another says "item goes here," and tying capacity to the open flag makes every feasible point a genuine packing.
