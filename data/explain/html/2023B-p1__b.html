The statement is true. The claim is only about the cost of a single pivoting step, not about how many pivots the whole simplex run performs (that number can be exponential). We check that one pivot is a fixed number of polynomial-size linear-algebra operations.

  1. Choosing the entering variable. The algorithm computes the reduced-cost vector and picks a coordinate \(i\) whose reduced cost signals that bringing it into the basis improves the objective. Forming the reduced costs is a matrix-vector computation on the input data, hence polynomial in the input length.
  2. Choosing the leaving variable. Given the entering column, the ratio test compares the current basic solution against that column entrywise and selects the coordinate \(j\) to remove from the basis. This is a linear scan of polynomially many ratios.
  3. Updating the basis. Swapping \(i\) in and \(j\) out requires recomputing the basis inverse and the associated basic solution, i.e. some matrix inversions and matrix multiplications. Each of these runs in polynomial time in the size of the matrices, which are bounded by the input dimensions.
Every ingredient of a pivot — reduced costs, ratio test, and the inverse/multiplication update — is a standard polynomial-time linear-algebra routine, so each pivoting step is polynomial in the input length. The open difficulty of simplex is the possible number of steps, not the cost per step.
