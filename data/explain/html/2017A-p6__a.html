We use one binary variable per element of \(S\). For each \(i\in S\) let \(x_i\) be a \(0/1\) variable, where \(x_i=1\) means that \(i\) is chosen for the hitting set and \(x_i=0\) means it is not. The chosen set is then \(X=\{i\in S:x_i=1\}\).

The condition that \(X\) is a hitting set is that it meets every subset in \(C\): for each \(D\in C\) we need \(X\cap D\neq\varnothing\), i.e. at least one element of \(D\) is chosen. Since \(\sum_{i\in D}x_i\) counts how many elements of \(D\) are chosen, "at least one" is exactly \(\sum_{i\in D}x_i\ge 1\).

We want a hitting set of smallest cardinality, and \(|X|=\sum_{i\in S}x_i\), so we minimize this sum. The program is

\[\min\ \sum_{i\in S}x_i\quad\text{s.t.}\quad \sum_{i\in D}x_i\ge 1\ \ \text{for all }D\in C,\qquad x_i\in\{0,1\}\ \ \text{for all }i\in S.\]

The \(\{0,1\}\) requirement forces each element to be either fully in or fully out, so feasible solutions are exactly the hitting sets and an optimal solution is a minimum hitting set.

Intuition. One yes/no switch per element, and "hit every set" just means each set has at least one switch turned on.
