Goal Turn the expected-\(cn\) selection algorithm into one that always runs in \(\le 25cn\) operations and is correct with probability \(\ge 1-\tfrac{1}{2^5}\).

Strategy Run capped attempts: abort any run once it passes \(2cn\) steps, retry up to 5 times with fresh randomness, and return the first run that finishes.

Key idea A run that exceeds twice its expected length is "unlucky"; by Markov that happens with probability at most \(\tfrac12\), and five independent unlucky runs is at most \(\tfrac{1}{2^5}\).

Why this move We want a hard time cap but the base algorithm only bounds expected time — capping each run and repeating trades a small failure chance for a guaranteed running time, and Markov is the one tool that needs only the expectation.

  1. Cap each run. Run the algorithm but stop a run the moment its step counter hits \(2cn\). Repeat at most 5 times, using independent randomness each time.
  2. Output rule. If some run finishes within its \(2cn\) budget, return its (correct) answer. If all 5 are aborted, just return the first array element as a guess.
  3. Bound the operations. Each run does at most \(2cn\) steps, so 5 runs do at most \(10cn\); with the counter bookkeeping the total stays under \(25cn\) always — a hard worst-case cap.
  4. Failure needs all to overshoot. The answer is wrong only if every run exceeded \(2cn\) steps, since any run that finishes returns the exact correct selection.
  5. Markov on one run. With \(\mathbb{E}[T(n)]\le cn\), Markov gives \(\Pr[T(n) > 2cn]\le \Pr[T(n)>2\mathbb{E}[T(n)]]\le \tfrac12\).
  6. Multiply independent runs. The 5 runs use independent coins, so \(\Pr[\text{all 5 overshoot}] \le \big(\tfrac12\big)^5 = \tfrac{1}{2^5}\). Hence the answer is correct with probability \(\ge 1-\tfrac{1}{2^5}\), and each extra retry cuts the failure chance in half.
