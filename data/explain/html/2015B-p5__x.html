We are given a Las Vegas algorithm \(A\): it is always correct, but its running time \(T(n)\) is random with expectation \(\mathbb{E}[T(n)]\le 10n\). We must build a Monte Carlo algorithm \(B\) that always runs in \(O(n)\) time and is correct with probability \(\ge 9/10\). The idea is to run \(A\) but cut it off after a fixed budget of steps, using \(A\) as a black box.

  1. Algorithm \(B\). Run \(A(x)\) for at most \(100n\) steps. If \(A\) finishes within that budget, output \(A\)'s answer. If \(A\) has not finished, halt it and output \(0\).
  2. Running time. By construction \(B\) never runs more than \(100n\) steps (plus the trivial cutoff overhead), so \(B\) runs in \(O(n)\) time on every execution — deterministically bounded.
  3. When can \(B\) err? If \(A\) finishes, its answer is correct (\(A\) is Las Vegas, always correct), so \(B\) is correct. The only way \(B\) can be wrong is when \(A\) fails to finish within \(100n\) steps and \(B\) outputs the default \(0\).
  4. Bounding that probability. \(T(n)\ge0\), so Markov's inequality applies: \[\Pr[\,T(n)\ge 100n\,]\le\frac{\mathbb{E}[T(n)]}{100n}\le\frac{10n}{100n}=\frac1{10}.\]

Thus \(B\) errs with probability at most \(1/10\), i.e. it is correct with probability at least \(9/10\). This bound uses only \(\mathbb{E}[T(n)]\le10n\), so it depends solely on the algorithm's internal randomness and not on the particular input \(x\), exactly as required.
