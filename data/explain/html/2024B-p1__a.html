True. Integer linear programming is NP-hard, because many NP-complete problems can be encoded as integer linear programs. For example, we saw in class a polynomial-time reduction from the maximum independent set problem to solving integer linear programs: given a graph \(G=(V,E)\), introduce a variable \(x_v\in\{0,1\}\) for each vertex, add the constraint \(x_u+x_v\le 1\) for every edge \((u,v)\), and maximize \(\sum_v x_v\); the optimum equals the size of the maximum independent set.

So a polynomial-time algorithm for integer linear programs would solve maximum independent set — an NP-complete problem — in polynomial time. Since an NP-complete problem would then be solvable in polynomial time, this would imply P=NP.

Intuition. ILP is NP-hard (independent set reduces to it), so a fast ILP solver would collapse P and NP.
