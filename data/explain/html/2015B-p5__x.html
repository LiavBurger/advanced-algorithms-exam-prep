Algorithm \(B\) uses \(A\) as a black box with a time budget:

  1. Run \(A(x)\) for at most \(100n\) steps.
  2. If \(A\) terminates within that budget, return its answer.
  3. Otherwise, halt \(A\) and return \(0\).

Running time: \(B\) never runs more than \(100n\) steps, so it runs in \(O(n)\) time on every input.

Correctness: if \(A\) terminates, its answer is correct, since \(A\) is a Las Vegas algorithm that always returns \(f(x)\). So \(B\) can only be wrong when \(A\) fails to finish within \(100n\) steps and \(B\) outputs the default \(0\). Since the running time \(T(n)\ge 0\) and \(\mathbb{E}[T(n)]\le 10n\), Markov's inequality gives

\[\Pr[T(n)\ge 100n]\;\le\;\frac{\mathbb{E}[T(n)]}{100n}\;\le\;\frac{10n}{100n}=\frac{1}{10}.\]

So \(B\) errs with probability at most \(1/10\), i.e. it is correct with probability at least \(9/10\). This bound uses only \(\mathbb{E}[T(n)]\le 10n\), so it depends on the algorithm's randomness and not on the particular input \(x\).

Intuition. A run much longer than average is rare, so cutting off at ten times the expected time almost always still lets \(A\) finish and answer correctly.
