When do I reach for this?

Any question about the global minimum cut of an undirected graph, or that asks you to count min-cuts. The whole method is one idea: if you keep merging random edges, a fixed min-cut has a decent chance of never being merged — and "decent chance × many repetitions = high probability".

  • "Find / approximate the min-cut" → run contraction, repeat, take the best.
  • "Prove a graph has at most \(\binom{n}{2}\) min-cuts" → use the survival lower bound as a counting argument.
  • Anything where a random merge might destroy a special structure → bound the per-step survival, multiply.

The algorithm

Definition Karger contraction: while \(|V|>2\), pick a uniformly random edge \(e=(u,v)\), merge \(u,v\) into one vertex, and delete self-loops (keep parallel edges). Output the cut given by the two surviving super-vertices.

Core tools

DEGREE / EDGE-COUNT BOUND
If the min-cut has size \(k\), then \(\deg(v)\ge k\) for all \(v\), so \[ |E|=\tfrac12\sum_{v}\deg(v)\ge \tfrac{k|V|}{2}. \] to lower-bound how many edges are still around, hence upper-bound the chance of hitting a cut edge
PER-STEP SURVIVAL
Fix one min-cut \((A,B)\). In iteration \(i\) (with \(|V|-i+1\) vertices left), \[ \Pr[e\text{ crosses }(A,B)]=\frac{k}{|E_i|}\le \frac{2}{|V|-i+1}. \] the event you must AVOID at every single step
Theorem A fixed min-cut survives all contractions with probability \[ \Pr[\text{survives}]\ge \prod_{i=1}^{n-2}\Big(1-\tfrac{2}{n-i+1}\Big)=\frac{2}{n(n-1)}=\binom{n}{2}^{-1}. \] Running \(O(n^2\log n)\) independent trials and keeping the best cut makes the failure probability tiny.

Worked example — the thinking

2024B P3. Prove a graph has at most \(\binom{n}{2}\) minimum cuts.

  1. Reframe counting as probability. Label the distinct min-cuts \(C_1,\dots,C_t\). One run outputs exactly one cut, so the events "run outputs \(C_j\)" are disjoint.
  2. Lower-bound each. Outputting \(C_j\) requires \(C_j\) to survive, so \(\Pr[\text{output }C_j]\ge \tfrac{2}{n(n-1)}\) — the same bound for every min-cut.
  3. Sum \(\le 1\). Disjoint events: \(1\ge \sum_{j=1}^t \Pr[\text{output }C_j]\ge t\cdot \tfrac{2}{n(n-1)}\).
  4. Solve. Rearranging gives \(t\le \tfrac{n(n-1)}{2}=\binom{n}{2}\). The probability bound became a counting bound — no algorithm needs to run.
Traps. Delete self-loops but keep parallel edges — they carry the multiplicity that makes edge sampling correct. The survival bound is for one fixed cut chosen before the run, not "some cut". Never assume the min-cut is unique. The \(2/(|V|-i+1)\) bound uses \(|E_i|\ge k(|V|-i+1)/2\), which needs the min-cut of the contracted graph to still be \(\ge k\).

Checklist

  1. Fix one target min-cut \((A,B)\) up front.
  2. Per step: \(\Pr[\text{hit a cut edge}]\le \tfrac{2}{\#\text{vertices left}}\).
  3. Multiply the survival factors → \(\ge 1/\binom{n}{2}\).
  4. To count cuts: disjoint outputs, sum probabilities \(\le 1\), solve for \(t\).
  5. To find the cut: repeat \(O(n^2\log n)\) times, keep the smallest.
