When do I reach for this?

This is the foundation layer. The moment a problem asks "how many on average", "expected running time", or "probability that something goes wrong", you break the big messy quantity into tiny 0/1 pieces and add them up.

  • "Expected number of X" → write X as a sum of indicators, one per potential X, then use linearity.
  • "Probability at least one bad thing happens" → union bound.
  • Quicksort / Quickselect runtime → write a recurrence over the random pivot, say what the expectation is over, solve.
  • "Convert Monte Carlo ↔ Las Vegas" or "ZPP/RP/BPP" → cap the runtime, bound failure with Markov, amplify by repeating.

Core tools

LINEARITY OF EXPECTATION
\[ \mathbb{E}\!\left[\sum_i X_i\right]=\sum_i \mathbb{E}[X_i],\qquad \mathbb{E}[aX+bY]=a\,\mathbb{E}[X]+b\,\mathbb{E}[Y] \] always, even when the \(X_i\) are dependent — you never need independence here
INDICATOR TRICK
Let \(Y_i\) be an indicator for the event \(A_i\). Then \(\mathbb{E}[Y_i]=\Pr[A_i]\), so \[ \mathbb{E}\!\left[\sum_i Y_i\right]=\sum_i \Pr[A_i]. \] counting problems: turn a count into a sum of yes/no events
UNION BOUND
\[ \Pr\!\left[\bigcup_i A_i\right]\le \sum_i \Pr[A_i] \] bounding the chance that ANY of several bad events occurs; no independence needed
MASTER THEOREM
For \(T(n)=a\,T(n/b)+\Theta(n^c)\): compare \(c\) with \(\log_b a\). E.g. \(T(n)=3T(n/4)+\Theta(n)\Rightarrow \Theta(n)\) since \(1>\log_4 3\). solving divide-and-conquer recurrences
Definition ZPP = Las Vegas (always correct, expected poly time). RP = one-sided error (rejects the "no" side sometimes). BPP = two-sided error \(\le 1/3\). Key facts: \(\mathrm{ZPP}=\mathrm{RP}\cap\mathrm{coRP}\), and \(\mathrm{RP}\subseteq\mathrm{BPP}\).

Worked example — the thinking

2018B P4. Randomized selection (find the \(k\)-th smallest) — prove \(\mathbb{E}[T(n)]=O(n)\).

  1. Whose randomness? The analysis is over the pivot coins, not the input. So the \(O(n)\) bound holds for every worst-case input — state this first.
  2. Set up the recurrence. A uniform pivot lands in each rank equally often, and we recurse on one side. Averaging over pivots gives \(\mathbb{E}[T(n)]\le \tfrac{2}{n}\sum_{k} \mathbb{E}[T(k)]+\Theta(n)\).
  3. Guess and verify. Guess \(\mathbb{E}[T(k)]\le ck\), plug into the sum, and check the constant \(c\) survives — that is the induction.
  4. Las Vegas → Monte Carlo. Cap each run at, say, twice the expected time; by Markov it fails with probability \(\le 1/2\). Run \(5\) capped trials: all fail with probability \(\le 2^{-5}\).
Traps. Do not assume independence to use linearity — you never need it. Conversely do not write \(\Pr[A\cap B]=\Pr[A]\Pr[B]\) unless independence is given. Always name what the expectation is taken over (coins vs. input). For Master Theorem, check which term dominates rather than pattern-matching.

Checklist

  1. Is the target an expected count, a runtime, or a failure probability?
  2. Count → one indicator per event, compute each \(\Pr[A_i]\), sum by linearity.
  3. "At least one" → union bound over the bad events.
  4. Runtime → recurrence over the random choice; state the expectation's source; solve.
  5. Monte Carlo ↔ Las Vegas → cap, bound by Markov, amplify.
