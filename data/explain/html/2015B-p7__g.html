Goal a polynomial-time algorithm that finds a minimum edge cover, plus a short correctness argument.

Strategy take a maximum matching, then add one cheap edge for each still-uncovered vertex; argue no cover can do better.

Key idea a matching covers two new vertices per edge — the most efficient covering possible — so building around a maximum matching minimizes the edge count.

Why this move "cover every vertex with few edges" begs for matching: each matching edge kills two birds at once, and matching is a poly-time tool from class.

  1. Algorithm. Compute a maximum matching \(M\) (poly time, e.g. the matching algorithm from class). It has \(|M|\) edges covering \(2|M|\) distinct vertices. For each of the \(|V|-2|M|\) still-uncovered vertices, add one arbitrary incident edge. (An edge cover exists since \(G\) is connected, so no vertex is isolated.)
  2. Size of the output. \(\text{ALG}=|M|+(|V|-2|M|)=|V|-|M|\), where \(|M|=\text{MAX-MATCHING}\).
  3. Lower bound on any cover. Take any optimal cover \(\mathrm{OPT}\) and assign each vertex to one \(\mathrm{OPT}\)-edge covering it. Each edge is assigned at most \(2\) vertices, and the edges assigned two vertices are vertex-disjoint — a matching — so there are at most \(\text{MAX-MATCHING}\) of them.
  4. Conclude. Counting shows \(\mathrm{OPT}\) uses at least \(|V|-\text{MAX-MATCHING}=\text{ALG}\) edges, so no cover beats ours. Intuitively: you can't cover the vertices with fewer edges than "one per vertex, minus a bonus for every pair a matching lets you share," and a maximum matching grabs every available bonus.
