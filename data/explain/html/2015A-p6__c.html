We combine parts (a) and (b) to show the algorithm uses at most one bin more than the optimum. Let \(x\) be the number of full bins and \(y\) the number of non-full bins it produces, so the algorithm uses \(x+y\) bins. Let \(1/k\) be the weight of the item that opened the last bin.

  1. Lower-bound the total weight. Each full bin holds weight exactly \(1\), contributing \(x\). By part (b), each non-full bin except the last-opened one holds at least \(1-\tfrac1k\); there are \(y-1\) such bins. So the total item weight is at least \[ x + \Big(1-\tfrac1k\Big)(y-1) = x + y - 1 - \tfrac{y}{k} + \tfrac1k. \]
  2. Use part (a). Part (a) gives \(y\le k-1\), hence \(\tfrac{y}{k}\le \tfrac{k-1}{k}<1\). Plugging \(\tfrac{y}{k}<1\) into the bound, the total weight is strictly greater than \(x+y-1-1 = x+y-2\).
  3. Compare with OPT. Every bin holds weight at most \(1\), so any valid packing needs at least (total weight) bins; in particular \(\mathrm{OPT}\ge \text{total weight} > x+y-2\). Since OPT is an integer, \(\mathrm{OPT}\ge x+y-1\).
The algorithm uses \(x+y\) bins while \(\mathrm{OPT}\ge x+y-1\), so it uses at most \(\mathrm{OPT}+1\) bins. This is an additive \(1\)-approximation.
